Exceptions & Error Handling

In this module you will learn how Python signals errors through exceptions, how to catch and handle them gracefully, how to raise your own exceptions, and how to build custom exception hierarchies. By the end you will be able to write robust programs that degrade gracefully instead of crashing unexpectedly.

Learning Objectives​

  • Understand what exceptions are and how Python raises them
  • Use try / except / else / finally blocks correctly
  • Catch specific exception types instead of bare except
  • Raise exceptions intentionally with raise
  • Define custom exception classes
  • Chain exceptions with raise ... from ...

Theory​

What Is an Exception?​

An exception is a Python object that signals that something went wrong at runtime. When Python raises an exception, normal execution stops and Python unwinds the call stack looking for a handler. If none is found, the program prints a traceback and exits.

Common built-in exceptions:

ExceptionRaised when
ValueErrorArgument has the right type but wrong value
TypeErrorOperation applied to wrong type
KeyErrorDict key not found
IndexErrorSequence index out of range
FileNotFoundErrorFile does not exist
ZeroDivisionErrorDivision by zero
AttributeErrorAttribute does not exist on object

See Built-in Exceptions for the full hierarchy.

try / except​

Wrap risky code in a try block and handle the error in an except block:

try:
    result = int("not a number")
except ValueError as e:
    print(f"Conversion failed: {e}")

You can catch multiple exception types:

try:
    value = data[key] / count
except KeyError:
    print("Key not found")
except ZeroDivisionError:
    print("Cannot divide by zero")
except (TypeError, ValueError) as e:
    print(f"Bad value: {e}")
tip

Always catch the most specific exception you expect. A bare except: (or except Exception:) hides bugs and makes debugging very hard.

else and finally​

  • The else block runs only when no exception was raised.
  • The finally block runs always — ideal for cleanup.
try:
    result = risky_operation()
except SomeError as e:
    print(f"Failed: {e}")
else:
    print(f"Success: {result}")   # runs only if no exception
finally:
    print("Cleanup always runs")  # runs regardless

See Handling Exceptions in the Python Tutorial.

Raising Exceptions​

Use raise to signal an error from your own code:

def set_age(age):
    if not isinstance(age, int):
        raise TypeError(f"age must be int, got {type(age).__name__}")
    if age < 0:
        raise ValueError(f"age cannot be negative: {age}")
    return age

Re-raise the current exception inside an except block simply with raise (no argument).

Custom Exception Classes​

Subclass Exception (or a more specific built-in) to create domain-specific errors:

class InsufficientFundsError(Exception):
    """Raised when a withdrawal exceeds the available balance."""
    def __init__(self, amount, balance):
        self.amount = amount
        self.balance = balance
        super().__init__(
            f"Cannot withdraw {amount}: balance is only {balance}"
        )
note

Custom exceptions make your API clearer. Callers can catch InsufficientFundsError specifically without catching unrelated ValueError exceptions from elsewhere.

Exception Chaining​

Use raise NewError(...) from original to preserve context when you translate one exception into another:

try:
    value = int(user_input)
except ValueError as e:
    raise ValueError(f"Invalid port number: {user_input!r}") from e

The original traceback is attached and shown with "The above exception was the direct cause of the following exception".

See Exception Chaining.
