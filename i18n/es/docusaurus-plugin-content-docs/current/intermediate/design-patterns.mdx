# Patrones de Diseño en Python

En este módulo aprenderás cómo los **patrones de diseño** clásicos se expresan en Python idiomático. Los patrones son soluciones reutilizables y probadas para problemas recurrentes de diseño de software. Las funciones de primera clase, los decoradores y el tipado dinámico de Python a menudo hacen que los patrones sean más concisos que en otros lenguajes. Al final podrás reconocer y aplicar los patrones Factory, Singleton, Observer, Strategy e Iterator en código real.

## Objetivos de Aprendizaje

- Entender por qué importan los patrones de diseño y cuándo aplicarlos
- Implementar el patrón **Factory** para desacoplar la creación de objetos
- Usar el patrón **Singleton** para garantizar una única instancia
- Aplicar el patrón **Observer** para comunicación basada en eventos
- Usar el patrón **Strategy** para intercambiar algoritmos en tiempo de ejecución
- Construir el patrón **Iterator** con `__iter__` y `__next__`

## Teoría

### ¿Por Qué los Patrones de Diseño?

Los patrones de diseño son planos arquitectónicos. No te dicen el código exacto a escribir — describen la *estructura* de una solución para que puedas adaptarla a tu problema. Aprenderlos te permite:

- Comunicar intención con otros desarrolladores usando un vocabulario compartido
- Evitar reinventar soluciones a problemas conocidos
- Escribir código más fácil de extender y probar

:::note
En Python, muchos patrones clásicos (Command, Template Method, Strategy) se pueden simplificar con funciones de primera clase en lugar de elaboradas jerarquías de clases. Los patrones pythónicos se apoyan en callables, closures y generadores.
:::

### Patrón Factory

Un **Factory** centraliza la creación de objetos, ocultando qué clase concreta se instancia. Esto desacopla el código cliente de los detalles de implementación:

```python
class Dog:
    def speak(self): return "Woof!"

class Cat:
    def speak(self): return "Meow!"

class AnimalFactory:
    _registry = {"dog": Dog, "cat": Cat}

    @classmethod
    def create(cls, kind):
        animal_class = cls._registry.get(kind)
        if animal_class is None:
            raise ValueError(f"Unknown animal: {kind!r}")
        return animal_class()

animal = AnimalFactory.create("dog")
print(animal.speak())   # Woof!
```

Consulta [Factory Method — Refactoring Guru](https://refactoring.guru/design-patterns/factory-method).

### Patrón Singleton

Un **Singleton** garantiza que solo puede existir una instancia de una clase. En Python, el enfoque más limpio sobreescribe `__new__`:

```python
class Config:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
            cls._instance.settings = {}
        return cls._instance

c1 = Config()
c2 = Config()
print(c1 is c2)   # True — same object
```

:::tip
Los Singletons son útiles para objetos de configuración, logging o pools de conexiones — cualquier cosa donde tenga sentido exactamente una instancia compartida. Sin embargo, pueden dificultar las pruebas porque llevan estado global.
:::

### Patrón Observer

El **Observer** (también llamado Publish/Subscribe o sistema de eventos) permite que los objetos se suscriban a eventos publicados por otro objeto. El publicador no necesita saber quién está escuchando:

```python
class EventEmitter:
    def __init__(self):
        self._listeners = {}

    def on(self, event, callback):
        self._listeners.setdefault(event, []).append(callback)

    def emit(self, event, *args, **kwargs):
        for cb in self._listeners.get(event, []):
            cb(*args, **kwargs)

emitter = EventEmitter()
emitter.on("login", lambda user: print(f"{user} logged in"))
emitter.emit("login", "Alice")   # Alice logged in
```

Consulta [Patrón Observer](https://refactoring.guru/design-patterns/observer).

### Patrón Strategy

El patrón **Strategy** define una familia de algoritmos y los hace intercambiables. En Python, las estrategias son a menudo funciones simples o callables:

```python
def bubble_sort(data):
    data = data[:]
    for i in range(len(data)):
        for j in range(len(data) - i - 1):
            if data[j] > data[j+1]:
                data[j], data[j+1] = data[j+1], data[j]
    return data

class Sorter:
    def __init__(self, strategy=sorted):
        self.strategy = strategy

    def sort(self, data):
        return self.strategy(data)

s = Sorter(strategy=bubble_sort)
print(s.sort([3, 1, 4, 1, 5]))   # [1, 1, 3, 4, 5]
```

:::tip
Cuando una estrategia puede expresarse como una única función, pasa la función directamente en lugar de envolverla en una clase. Las funciones de primera clase de Python hacen que este patrón sea muy ligero.
:::

### Patrón Iterator

Un **Iterator** proporciona acceso secuencial a elementos sin exponer la estructura de datos subyacente. En Python, implementas `__iter__` y `__next__`:

```python
class CountDown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        val = self.current
        self.current -= 1
        return val

for n in CountDown(3):
    print(n)   # 3, 2, 1
```

Alternativamente, usa una **función generadora** con `yield`:

```python
def count_down(start):
    while start > 0:
        yield start
        start -= 1
```

Consulta [Tipos de Iteradores](https://docs.python.org/3/library/stdtypes.html#iterator-types) y [Generadores](https://docs.python.org/3/reference/expressions.html#generator-expressions).

<PythonRunner
  title="Inventory Management System"
  difficulty="difícil"
  initialCode={`# Build a mini inventory system that uses three patterns together:
#
# 1. FACTORY — ItemFactory.create(kind, name, price, qty)
#    Supported kinds: "physical", "digital"
#    PhysicalItem: has weight attribute
#    DigitalItem: has download_url attribute
#
# 2. OBSERVER — Inventory notifies observers when stock falls below threshold
#    LowStockObserver.update(item) appends f"LOW STOCK: {item.name} ({item.qty} left)"
#    to self.warnings when item.qty < 5
#
# 3. ITERATOR — Inventory is iterable, yielding items one by one
#
# Inventory:
# - add(item)
# - sell(name, qty) — reduces qty, notifies observers
# - subscribe(observer) / unsubscribe(observer)
# - __iter__ / __next__ for iteration

class PhysicalItem:
    def __init__(self, name, price, qty, weight):
        self.name = name
        self.price = price
        self.qty = qty
        self.weight = weight

class DigitalItem:
    def __init__(self, name, price, qty, download_url):
        self.name = name
        self.price = price
        self.qty = qty
        self.download_url = download_url

class ItemFactory:
    @classmethod
    def create(cls, kind, name, price, qty, **kwargs):
        if kind == "physical":
            return PhysicalItem(name, price, qty, **kwargs)
        elif kind == "digital":
            return DigitalItem(name, price, qty, **kwargs)
        raise ValueError(f"Unknown item kind: {kind!r}")

class LowStockObserver:
    def __init__(self):
        self.warnings = []

    def update(self, item):
        if item.qty < 5:
            self.warnings.append(f"LOW STOCK: {item.name} ({item.qty} left)")

class Inventory:
    def __init__(self):
        self._items = {}
        self._observers = []
        self._iter_keys = None
        self._iter_index = 0

    def add(self, item):
        self._items[item.name] = item

    def subscribe(self, observer):
        self._observers.append(observer)

    def unsubscribe(self, observer):
        self._observers.remove(observer)

    def sell(self, name, qty):
        item = self._items[name]
        item.qty -= qty
        for obs in self._observers:
            obs.update(item)

    def __iter__(self):
        self._iter_keys = list(self._items.keys())
        self._iter_index = 0
        return self

    def __next__(self):
        if self._iter_index >= len(self._iter_keys):
            raise StopIteration
        key = self._iter_keys[self._iter_index]
        self._iter_index += 1
        return self._items[key]

# Test

watcher = LowStockObserver()
inv.subscribe(watcher)

inv.add(ItemFactory.create("digital", "eBook", 4.99, 100, download_url="http://example.com"))

inv.sell("Widget", 7)   # qty drops to 3 → triggers LOW STOCK
inv.sell("Widget", 1)   # qty drops to 2 → triggers LOW STOCK again

print(watcher.warnings)
# ['LOW STOCK: Widget (3 left)', 'LOW STOCK: Widget (2 left)']

names = [item.name for item in inv]
print(names)   # ['Widget', 'eBook']
`}

    { input: "len(watcher.warnings)", expected: "2", description: "Should have 2 low-stock warnings" },
    { input: "[item.name for item in inv]", expected: "['Widget', 'eBook']", description: "Inventory should be iterable" },
  ]}
