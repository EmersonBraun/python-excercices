# Excepciones y Manejo de Errores

En este módulo aprenderás cómo Python señala errores a través de **excepciones**, cómo atraparlas y manejarlas con elegancia, cómo lanzar tus propias excepciones y cómo construir jerarquías de excepciones personalizadas. Al final podrás escribir programas robustos que degradan con gracia en lugar de fallar inesperadamente.

## Objetivos de Aprendizaje

- Entender qué son las excepciones y cómo Python las lanza
- Usar bloques `try` / `except` / `else` / `finally` correctamente
- Atrapar tipos de excepción específicos en lugar de `except` genérico
- Lanzar excepciones intencionalmente con `raise`
- Definir clases de excepción personalizadas
- Encadenar excepciones con `raise ... from ...`

---

## Teoría

### ¿Qué Es una Excepción?

Una excepción es un objeto Python que señala que algo salió mal en tiempo de ejecución. Cuando Python lanza una excepción, la ejecución normal se detiene y Python deshace la pila de llamadas buscando un manejador. Si no se encuentra ninguno, el programa imprime un **traceback** y termina.

Excepciones integradas comunes:

| Excepción | Lanzada cuando |
|-----------|---------------|
| `ValueError` | El argumento tiene el tipo correcto pero valor incorrecto |
| `TypeError` | Operación aplicada al tipo incorrecto |
| `KeyError` | Clave de diccionario no encontrada |
| `IndexError` | Índice de secuencia fuera de rango |
| `FileNotFoundError` | El archivo no existe |
| `ZeroDivisionError` | División por cero |
| `AttributeError` | El atributo no existe en el objeto |

Consulta [Excepciones Integradas](https://docs.python.org/3/library/exceptions.html) para la jerarquía completa.

### `try` / `except`

Envuelve el código riesgoso en un bloque `try` y maneja el error en un bloque `except`:

```python
try:
    result = int("not a number")
except ValueError as e:
    print(f"Conversion failed: {e}")
```

Puedes atrapar múltiples tipos de excepción:

```python
try:
    value = data[key] / count
except KeyError:
    print("Key not found")
except ZeroDivisionError:
    print("Cannot divide by zero")
except (TypeError, ValueError) as e:
    print(f"Bad value: {e}")
```

:::tip
Siempre atrapa la excepción **más específica** que esperas. Un `except:` genérico (o `except Exception:`) oculta errores y dificulta mucho la depuración.
:::

### `else` y `finally`

- El bloque `else` se ejecuta **solo cuando no se lanzó ninguna excepción**.
- El bloque `finally` se ejecuta **siempre** — ideal para limpieza.

```python
try:
    result = risky_operation()
except SomeError as e:
    print(f"Failed: {e}")
else:
    print(f"Success: {result}")   # runs only if no exception
finally:
    print("Cleanup always runs")  # runs regardless
```

Consulta [Manejo de Excepciones](https://docs.python.org/3/tutorial/errors.html#handling-exceptions) en el Tutorial de Python.

### Lanzar Excepciones

Usa `raise` para señalar un error desde tu propio código:

```python
def set_age(age):
    if not isinstance(age, int):
        raise TypeError(f"age must be int, got {type(age).__name__}")
    if age < 0:
        raise ValueError(f"age cannot be negative: {age}")
    return age
```

Vuelve a lanzar la excepción actual dentro de un bloque `except` simplemente con `raise` (sin argumento).

### Clases de Excepción Personalizadas

Crea subclases de `Exception` (o de un integrado más específico) para crear errores específicos del dominio:

```python
class InsufficientFundsError(Exception):
    """Raised when a withdrawal exceeds the available balance."""
    def __init__(self, amount, balance):
        self.amount = amount
        self.balance = balance
        super().__init__(
            f"Cannot withdraw {amount}: balance is only {balance}"
        )
```

:::note
Las excepciones personalizadas hacen tu API más clara. Los llamadores pueden atrapar `InsufficientFundsError` específicamente sin atrapar excepciones `ValueError` no relacionadas de otros lugares.
:::

### Encadenamiento de Excepciones

Usa `raise NewError(...) from original` para preservar el contexto al traducir una excepción en otra:

```python
try:
    value = int(user_input)
except ValueError as e:
    raise ValueError(f"Invalid port number: {user_input!r}") from e
```

El traceback original se adjunta y se muestra con "The above exception was the direct cause of the following exception".

Consulta [Encadenamiento de Excepciones](https://docs.python.org/3/tutorial/errors.html#exception-chaining).
