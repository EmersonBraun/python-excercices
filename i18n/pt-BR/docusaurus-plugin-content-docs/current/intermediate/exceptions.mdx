# Exceções & Tratamento de Erros

Neste módulo você vai aprender como o Python sinaliza erros através de **exceções**, como capturá-las e tratá-las com elegância, como lançar suas próprias exceções e como construir hierarquias de exceções personalizadas. Ao final você será capaz de escrever programas robustos que degradam graciosamente em vez de travar inesperadamente.

## Objetivos de Aprendizagem

- Entender o que são exceções e como o Python as lança
- Usar blocos `try` / `except` / `else` / `finally` corretamente
- Capturar tipos específicos de exceção em vez de `except` genérico
- Lançar exceções intencionalmente com `raise`
- Definir classes de exceção personalizadas
- Encadear exceções com `raise ... from ...`

---

## Teoria

### O Que É uma Exceção?

Uma exceção é um objeto Python que sinaliza que algo deu errado em tempo de execução. Quando o Python lança uma exceção, a execução normal para e o Python desfaz a pilha de chamadas procurando um tratador. Se nenhum for encontrado, o programa imprime um **traceback** e encerra.

Exceções embutidas comuns:

| Exceção | Lançada quando |
|---------|----------------|
| `ValueError` | Argumento tem o tipo certo mas valor errado |
| `TypeError` | Operação aplicada ao tipo errado |
| `KeyError` | Chave de dicionário não encontrada |
| `IndexError` | Índice de sequência fora do intervalo |
| `FileNotFoundError` | Arquivo não existe |
| `ZeroDivisionError` | Divisão por zero |
| `AttributeError` | Atributo não existe no objeto |

Consulte [Exceções Embutidas](https://docs.python.org/3/library/exceptions.html) para a hierarquia completa.

### `try` / `except`

Envolva código arriscado em um bloco `try` e trate o erro em um bloco `except`:

```python
try:
    result = int("not a number")
except ValueError as e:
    print(f"Conversion failed: {e}")
```

Você pode capturar múltiplos tipos de exceção:

```python
try:
    value = data[key] / count
except KeyError:
    print("Key not found")
except ZeroDivisionError:
    print("Cannot divide by zero")
except (TypeError, ValueError) as e:
    print(f"Bad value: {e}")
```

:::tip
Sempre capture a exceção **mais específica** que você espera. Um `except:` genérico (ou `except Exception:`) esconde bugs e torna a depuração muito difícil.
:::

### `else` e `finally`

- O bloco `else` é executado **apenas quando nenhuma exceção foi lançada**.
- O bloco `finally` é executado **sempre** — ideal para limpeza.

```python
try:
    result = risky_operation()
except SomeError as e:
    print(f"Failed: {e}")
else:
    print(f"Success: {result}")   # executa apenas sem exceção
finally:
    print("Cleanup always runs")  # executa independentemente
```

Consulte [Tratamento de Exceções](https://docs.python.org/3/tutorial/errors.html#handling-exceptions) no Tutorial Python.

### Lançando Exceções

Use `raise` para sinalizar um erro a partir do seu próprio código:

```python
def set_age(age):
    if not isinstance(age, int):
        raise TypeError(f"age must be int, got {type(age).__name__}")
    if age < 0:
        raise ValueError(f"age cannot be negative: {age}")
    return age
```

Relance a exceção atual dentro de um bloco `except` simplesmente com `raise` (sem argumento).

### Classes de Exceção Personalizadas

Faça subclasse de `Exception` (ou de um embutido mais específico) para criar erros específicos do domínio:

```python
class InsufficientFundsError(Exception):
    """Raised when a withdrawal exceeds the available balance."""
    def __init__(self, amount, balance):
        self.amount = amount
        self.balance = balance
        super().__init__(
            f"Cannot withdraw {amount}: balance is only {balance}"
        )
```

:::note
Exceções personalizadas tornam sua API mais clara. Os chamadores podem capturar `InsufficientFundsError` especificamente sem capturar exceções `ValueError` não relacionadas de outros lugares.
:::

### Encadeamento de Exceções

Use `raise NewError(...) from original` para preservar o contexto ao traduzir uma exceção em outra:

```python
try:
    value = int(user_input)
except ValueError as e:
    raise ValueError(f"Invalid port number: {user_input!r}") from e
```

O traceback original é anexado e mostrado com "The above exception was the direct cause of the following exception".

Consulte [Encadeamento de Exceções](https://docs.python.org/3/tutorial/errors.html#exception-chaining).
